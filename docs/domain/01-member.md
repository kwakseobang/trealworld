# Domain 01. 회원

- 상태: 승인 (2026-11-16). 수정 (2026-11-17): R4의 길이 제한과 포트의 위치를 고쳤다. 수정 (2026-11-17, 작업 4): 비밀번호를 값 객체(`Password`)로 적었다.
- 범위: [Spec 01](../spec/01-member-signup-login.md)에 필요한 것만 다룬다.

## 용어

한 개념에는 한 용어만 쓴다. 문서, 대화, 코드에서 같은 말을 쓴다.

| 용어 | 코드 이름 | 뜻 |
|---|---|---|
| 방문자 | — | 로그인하지 않은 사람 |
| 회원 | `Member` | 가입한 사람. 이 도메인의 중심이다 |
| 사용자 이름 | `Username` | 회원이 정한 공개 이름. 회원마다 다르다 |
| 이메일 | `Email` | 회원의 이메일 주소. 로그인할 때 쓴다. 회원마다 다르다 |
| 비밀번호 | `Password` | 회원만 아는 원문. 저장하지 않는다 |
| 비밀번호 해시 | `PasswordHash` | 비밀번호를 되돌릴 수 없게 바꾼 값. 이것만 저장한다 |
| 가입 | `register` | 방문자가 회원이 되는 일 |
| 로그인 | `login` | 회원이 이메일과 비밀번호로 자기를 증명하는 일 |
| 액세스 토큰 | `AccessToken` | 로그인의 증거. 이후의 요청에 낸다 |

쓰지 않는 말: "유저", "사용자"(회원으로 쓴다), "계정", "닉네임"(사용자 이름으로 쓴다).

## 모델

- **회원**이 유일한 애그리거트다. 사용자 이름, 이메일, 비밀번호 해시를 가진다.
- **이메일**, **사용자 이름**, **비밀번호 해시**는 값 객체다. 자기의 형식 규칙을 스스로 검사한다.
- **비밀번호**도 값 객체다. 길이의 규칙(R4)을 스스로 검사한다. 회원은 비밀번호를 가지지 않는다. 가입과 로그인의 동안에만 있다.
- **액세스 토큰**은 도메인 모델이 아니다. 인증 기술의 산출물이다. 도메인은 "누가 요청했는가"(회원의 식별자)만 안다.

## 규칙

| ID | 규칙 | 지키는 곳 |
|---|---|---|
| R1 | 회원에게는 사용자 이름, 이메일, 비밀번호 해시가 항상 있다. | 회원 |
| R2 | 이메일은 올바른 형식이다. 소문자로 바꿔서 저장한다. | 이메일 |
| R3 | 사용자 이름은 비어 있지 않다. 앞뒤 공백을 지운다. | 사용자 이름 |
| R4 | 비밀번호는 8자 이상이고, UTF-8로 72바이트 이하다. 문자 종류의 조건은 없다. 한 자는 유니코드의 코드 포인트 하나다. | 비밀번호 (가입이 만든다) |
| R5 | 비밀번호의 원문은 저장하지 않는다. 회원은 해시만 가진다. | 회원 |
| R6 | 이메일은 회원마다 다르다. | 가입 |
| R7 | 사용자 이름은 회원마다 다르다. | 가입 |
| R8 | 로그인은 이메일로 회원을 찾고, 비밀번호가 해시와 맞는지 확인한다. | 로그인 |
| R9 | 로그인이 실패하면 이유(없는 이메일, 틀린 비밀번호)를 구분하지 않는다. | 로그인 |
| R10 | 회원은 자기의 정보만 조회한다. | 조회 |

R6과 R7은 회원 하나가 혼자 지킬 수 없다. 다른 회원을 알아야 하기 때문이다. 그래서 가입을 처리하는 곳이 저장소에 물어서 지킨다.

R4의 "72바이트"는 도메인에서 나온 숫자가 아니다. 해시 기술(BCrypt)의 제한이다. 기술의 제한이 규칙에 들어온 유일한 곳이다. 이유는 [ADR-0003](../adr/0003-authentication.md)에 있다.

## 규칙이 밖에 기대는 것

도메인은 기술을 모른다. 아래의 두 가지는 `application`의 나가는 포트가 된다. `domain`에는 인터페이스를 두지 않는다 ([ADR-0002](../adr/0002-hexagonal-architecture.md)).

- 회원을 저장하고, 이메일이나 사용자 이름으로 찾는 것
- 비밀번호를 해시로 바꾸고, 비밀번호가 해시와 맞는지 확인하는 것
