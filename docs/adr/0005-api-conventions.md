# ADR-0005. API 규약

- 상태: 승인 (2026-11-16). AI가 제안하고 사용자가 승인했다.

## 맥락

원본의 API 모양을 따르지 않아도 된다 (킥오프 6.6). Spec은 API의 모양을 정하지 않는다. 그래서 여기에서 정한다.

## 결정

| 목표 | 요청 | 성공 |
|---|---|---|
| 가입 | `POST /api/members` | 201 |
| 로그인 | `POST /api/auth/login` | 200 |
| 내 정보 조회 | `GET /api/members/me` | 200 |

실패의 상태 코드:

| 경우 | 코드 |
|---|---|
| 값이 비었거나 형식이 틀리다 | 400 |
| 로그인 실패, 토큰이 없거나 틀리다 | 401 |
| 이메일이나 사용자 이름이 이미 있다 | 409 |

- 요청과 응답은 JSON이다. 원본의 `{"user": {...}}` 같은 겉껍질은 쓰지 않는다.
- 오류의 본문은 RFC 9457 Problem Details 형식이다. Spring의 `ProblemDetail`을 쓴다.
- 값 검증의 오류에는 어느 필드가 문제인지 넣는다.

## 결과

- 원본과 다른 점: 경로(`/users` → `/members`), 겉껍질 없음, 검증 오류 422 → 400, 오류 형식.
- 원본의 Hurl 테스트는 이 API에서 통과하지 않는다. 의도한 것이다.

## 버린 대안

- 원본의 모양을 그대로 쓴다: 호환은 목표가 아니다. 도메인 용어(회원)와 경로(`users`)가 어긋난다.
