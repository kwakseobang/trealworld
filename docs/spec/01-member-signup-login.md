# Spec 01. 회원 가입 · 로그인 · 내 정보 조회

- 상태: 승인 (2026-11-16). 수정 (2026-11-17): 검토에서 찾은 빈틈을 닫았다. AC-1.4, 1.7, 2.4를 고치고 AC-1.8, 2.5, 3.5를 더했다.
- 슬라이스: 가입 → 로그인 → 회원 정보 조회 (킥오프 6.8)
- 용어: [도메인 모델](../domain/01-member.md)을 따른다.

이 문서는 **무엇을** 만드는지만 말한다. API의 모양과 기술은 [ADR](../adr/)에 있다.

## 목표 1. 방문자가 회원으로 가입한다

방문자가 사용자 이름, 이메일, 비밀번호를 내고 회원이 된다.

| ID | 수용 기준 |
|---|---|
| AC-1.1 | 올바른 값으로 가입하면 회원이 생긴다. 결과로 사용자 이름과 이메일을 받는다. |
| AC-1.2 | 사용자 이름, 이메일, 비밀번호 중 하나라도 비어 있으면 거부한다. 어느 값이 문제인지 알려준다. |
| AC-1.3 | 이메일의 형식이 틀리면 거부한다. |
| AC-1.4 | 비밀번호가 8자보다 짧거나, UTF-8로 72바이트보다 길면 거부한다. |
| AC-1.5 | 이미 있는 이메일이면 거부한다. |
| AC-1.6 | 이미 있는 사용자 이름이면 거부한다. |
| AC-1.7 | 어떤 결과에도 비밀번호와 비밀번호 해시가 들어 있지 않다. |
| AC-1.8 | 대소문자만 다른 이메일은 이미 있는 이메일로 본다. |

## 목표 2. 회원이 로그인한다

회원이 이메일과 비밀번호를 내고 액세스 토큰을 받는다.

| ID | 수용 기준 |
|---|---|
| AC-2.1 | 이메일과 비밀번호가 맞으면 액세스 토큰을 받는다. |
| AC-2.2 | 비밀번호가 틀리면 거부한다. |
| AC-2.3 | 없는 이메일이면 거부한다. AC-2.2와 구분할 수 없는 결과를 준다. |
| AC-2.4 | 이메일이나 비밀번호가 비어 있거나, 이메일의 형식이 틀리면 거부한다. 값의 오류로 알려준다. AC-2.2와 다른 결과다. |
| AC-2.5 | 이메일의 대소문자가 가입할 때와 달라도 로그인된다. |

## 목표 3. 회원이 자기 정보를 조회한다

로그인한 회원이 액세스 토큰을 내고 자기 정보를 받는다.

| ID | 수용 기준 |
|---|---|
| AC-3.1 | 유효한 액세스 토큰을 내면 자기의 사용자 이름과 이메일을 받는다. |
| AC-3.2 | 액세스 토큰이 없으면 거부한다. |
| AC-3.3 | 액세스 토큰이 위조됐거나 만료됐으면 거부한다. |
| AC-3.4 | 다른 회원의 정보는 조회할 수 없다. 조회 대상은 항상 토큰의 주인이다. |
| AC-3.5 | 토큰이 유효해도 그 주인인 회원이 없으면 거부한다. |

## 범위 밖

- 회원 정보 수정, 탈퇴
- 소개 글(`bio`)과 프로필 이미지(`image`). 원본에서는 가입 때 항상 비어 있고, 수정으로만 채운다.
- 로그아웃, 토큰 갱신
- 이메일 인증, 비밀번호 재설정

## 원본과 다른 점

| 항목 | 원본 | 이 spec | 이유 |
|---|---|---|---|
| 가입의 결과 | 토큰을 함께 준다 | 토큰을 주지 않는다 | 슬라이스에 로그인 단계가 따로 있다 |
| 가입 때 비밀번호 길이 | 빈 값만 검사한다 | 8자 이상, 72바이트 이하 | 원본은 길이 규칙을 수정에만 적용한다. 가입에도 같은 규칙이 맞다 |

## 확정한 가정

AI가 제안하고 사용자가 승인했다 (2026-11-16).

1. 이메일은 대소문자를 구분하지 않는다. `A@x.com`과 `a@x.com`은 같은 이메일이다.
2. 사용자 이름은 대소문자를 구분한다.
3. 가입은 토큰을 주지 않는다.
4. 비밀번호의 최대 길이는 UTF-8로 72바이트다. 처음에는 64자였다. BCrypt의 제한에 맞춰 사용자가 바꿨다 (2026-11-17). 한글만 쓰면 24자까지다.

## 받아들인 한계

- 이메일이 가입돼 있는지는 가입 요청으로 알 수 있다 (AC-1.5). AC-2.3의 보호는 로그인에만 있다. 원본도 같다.
- 로그인의 응답 시간이 경우마다 다를 수 있다. 이 슬라이스에서는 다루지 않는다.

## 근거

| 의도 | 원본에서 읽은 곳 |
|---|---|
| 가입에 세 값이 필요하다, 빈 값과 형식을 거부한다 | `hurl/errors_auth.hurl` (Register empty/malformed) |
| 이메일과 사용자 이름은 유일하다 | `hurl/errors_auth.hurl` (Register duplicate) |
| 로그인 실패의 이유를 드러내지 않는다 | `hurl/errors_auth.hurl` (Login wrong password → `credentials invalid`) |
| 비밀번호는 8자 이상이다 | `hurl/errors_auth.hurl` (NIST 800-63B 주석) |
| 가입과 로그인은 인증 없이 된다 | `openapi.yml` (`security` 항목 없음). 킥오프 가설 2의 반례다 |
| 토큰이 없으면 내 정보를 볼 수 없다 | `hurl/errors_auth.hurl` (GET /user no auth) |
